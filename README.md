## Протокол тестирования (curl)
Для симуляции прохождения "по цепочке" через Nginx, мы используем кастомный заголовок X-Next-Upstream, который наш конфиг считывает и превращает в динамический proxy_pass. Это позволяет одной командой curl построить любую цепочку.

### Тест 1: Прямой запрос через один Nginx
Условие: Пользователь идет на nginx1, тот сразу отправляет в app.
Ожидаемый результат: В X-Forwarded-For должен быть только ваш IP (для Docker на localhost это обычно IP шлюза, например, 172.20.0.1).

```bash
curl -s http://localhost:8081 | grep X-Forwarded-For
```
Вывод:

    X-Forwarded-For: 172.20.0.1

### Тест 2: Запрос по цепочке (nginx1 -> nginx2 -> app)
Условие: Пользователь идет на nginx1, говорит ему переслать на nginx2, а тот пересылает в app.
Ожидаемый результат: В X-Forwarded-For должна быть вся цепочка: [IP пользователя], [IP nginx1].

```bash
curl -s -H "X-Next-Upstream: nginx2" http://localhost:8081 | grep X-Forwarded-For
```
Вывод (IP нод могут незначительно отличаться):


    X-Forwarded-For: 172.20.121.1, 172.20.121.2
(Здесь 172.20.121.1 — вы, 172.20.121.2 — внутренний IP nginx1 в сети Docker).

### Тест 3: Длинная цепочка (nginx1 -> nginx2 -> nginx3 -> app)
Условие: Запрос проходит через все три прокси.
```bash
curl -s -H "X-Next-Upstream: nginx2" -H "X-Next-Upstream-2: nginx3" http://localhost:8081
```

### Тест 4: Защита от злоумышленника (Подмена заголовка)
Условие: Недобросовестный пользователь пытается умышленно передать фейковый IP 1.1.1.1 через заголовок X-Forwarded-For.
Ожидаемый результат: Фейковый IP полностью игнорируется на первом же Nginx. В итоговом логе приложения его быть не должно.

```bash
curl -s -H "X-Forwarded-For: 1.1.1.1" http://localhost:8081 | grep X-Forwarded-For
```
Вывод:


    X-Forwarded-For: 172.20.0.1
Фальшивый 1.1.1.1 успешно стерт.

### Тест 5: Подмена заголовка при работе в цепочке
Условие: Пользователь шлет фейковый 9.9.9.9 и отправляет запрос по цепочке nginx1 -> nginx2 -> app.
Ожидаемый результат: Фейк уничтожается на nginx1, а легитимная цепочка пользователь -> nginx1 строится дальше.
```bash
curl -s -H "X-Forwarded-For: 9.9.9.9" -H "X-Next-Upstream: nginx2" http://localhost:8081 | grep X-Forwarded-For
```
Вывод:


    X-Forwarded-For: 172.20.0.1, 172.20.0.2
Как видим, 9.9.9.9 не попал в финальный заголовок, при этом цепочка между Nginx отработала идеально.
